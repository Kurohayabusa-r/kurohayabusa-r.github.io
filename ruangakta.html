RuangAkta.

A document workspace that helps notary offices turn source text into structured, editable Word documents.

The problem

Preparing notarial documents involves more than entering text. Staff need consistent formatting, reusable office templates, and a way to revisit earlier work while keeping the result editable in Word.

RuangAkta brings these steps into a single web application, with tools for preparing PK KI documents and reviewing common text and formatting issues before export.

What I built

Document preparation

Source-text processing and formatting tools, with support for transferring bold and italic formatting from a reference Word document and generating .docx files in the browser.

Text checks

Findings for unfilled placeholders, possible numbering gaps, long lines, and mismatches between numbers and their written forms. Findings link back to the relevant editor text.

Reusable office work

Office templates and named saved documents that can be reopened from another device. Document history keeps up to five snapshots for comparison and restoration.

Accounts & access

Office registration and login, account-separated drafts, office feature access, and an administration panel for customer access and subscription periods.

Engineering choices

Server processing, browser export

Python handles text processing and document checks. Reference Word files and .docx generation stay in the browser. This keeps document processing separate from Word formatting and export.

Explicit persistence

Source text sent for processing is handled temporarily. Office templates and named documents are stored when users choose to save them; browser drafts remain local to the account and device.

Access at the office boundary

PostgreSQL on Neon supports the deployed application on Render. Passwords use salted scrypt hashes, sessions use HttpOnly cookies, and document endpoints enforce session, office-access, size, and processing limits.

Automated verification

Python and Node.js tests cover backend behavior and browser document logic. GitHub Actions runs the test workflow, and production client assets are built with esbuild.

A note on scope

This project connects my experience with business workflows to application development: translating detailed office requirements into document tools, access controls, and repeatable tests.

The document checker highlights text and formatting issues. Legal review and final document approval remain with the notary office.

The source repository is private. This overview describes the application without exposing office documents or account data.
